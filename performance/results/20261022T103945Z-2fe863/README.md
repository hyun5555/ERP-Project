# 포트폴리오용 1천 건 성능 검증

2026-10-22. 최종 선택 범위는 **1천 건·동일 조건 3반복**이다. 추가 규모는 사용자 요청으로 측정을 중단하고 평가에서 제외했다. 모든 성능 전용 앱·DB는 종료했으며 개발 source 앱·DB·첨부는 보존했다. [범위·종료 기록](portfolio-scope.json).

native MySQL 8.4.11·Java 21·production WAR, macOS arm·CPU 10개·메모리 32GiB에서 측정했다. 전용 DB에 공지·결재·메시지 각각 1천 건, 결재선 3천 개·방 100개·첨부 50개를 추가했다. 기존 seed는 유지하고 실제 건수는 [manifest](1000/manifest.json)에 기록했다. 로그인·워밍업은 측정 표본에서 제외했다. API는 사례별 1/5 폐루프 작업자, 전달은 1/5개 방, 브라우저는 1440×900·Chromium·cold/warm으로 나눴다.

| 항목 | 정상 / 시도 | 실패 |
|---|---:|---:|
| API 11개 사례 | 9,900 / 9,900 | 0 |
| 수신자 MESSAGE 전달 | 1,800 / 1,800 | 0 |
| 재접속 복구 | 18 / 18 | 0 |
| DB 저장·중복 검사 / 초기 상태 | 18 / 18, 6 / 6 | 0 |
| 브라우저 6개 사례 × cold/warm | 360 / 360 | 0 |

반복별 nearest-rank p95이며 API는 작업자 5명, 전달은 방 5개 조건이다.

| 사례 | 1회 | 2회 | 3회 |
|---|---:|---:|---:|
| 대시보드 API | 8.229ms | 7.828ms | 7.754ms |
| 완료 결재 부서 조회 API | 8.689ms | 8.681ms | 7.633ms |
| 공지 첫 페이지 API | 2.180ms | 1.271ms | 1.247ms |
| 대화방 목록 API | 6.659ms | 6.440ms | 5.349ms |
| 수신자 메시지 전달 | 2.623ms | 1.696ms | 1.538ms |

검색의 실제 클릭→정확한 결과 DOM 완료 표본 60개의 p95는 44.3ms였다. 브라우저 longtask는 관측 0개이며 LCP는 123개가 미관측 null이다. 미관측 값을 0으로 계산하지 않는다. DOM·rAF 완료를 paint 완료나 현장 INP로 표현하지 않는다. 브라우저 cold context는 DB·OS 캐시 초기화를 의미하지 않는다.

1천 건에서는 즉시 해결해야 할 성능 장애가 재현되지 않았다. 대시보드의 5회 COUNT와 완료 조회가 상대적으로 큰 비용을 보였으며, 실제 SQL·실행 계획을 남겼다. 이 결과만으로 대량 성능 개선이나 최대 동시 사용자 수를 주장하지 않는다.

API Tester(`/root/performance_independent_review`)가 원문에서 요약 126개 그룹을 재계산해 분모·평균·p50·p95·최댓값·실패율 일치를 확인했다. 전달 ID 1,800개 유일성, 복구 18회×10개 ID, DB/콜백 18회, 초기 상태 6회도 대조했다. SQL은 SELECT 24개×ANALYZE 3회이며 소스·WAR 내 Mapper·번들 해시가 일치했다.
