# 로컬 LLM 챗봇 MVP 설계·구현 기록

## 1. 범위

이번 단계는 벡터 DB와 범용 사내 검색을 제외하고, 로그인 사용자가 실제로 확인할 수 있는 최근 공지와 처리 대기 결재만 SQL로 조회해 로컬 LLM에 전달한다.

```text
React ChatPanel
        ↓ POST /api/ai/chat (SSE)
AiController
        ↓
AiService
   ├─ NoticeMapper: 전사 또는 사용자 부서 공지 5개
   ├─ ApprovalMapper: 현재 결재자의 대기 항목 5개
   └─ LocalLlmClient: Ollama /api/generate
```

## 2. 구현 내용

1. 질문은 공백 제외 1~500자로 제한한다.
2. 결재는 로그인 사번이 결재선에 있고 현재 상태가 `대기`인 문서만 조회한다.
3. 공지는 전사 코드 `999` 또는 로그인 사용자의 부서 코드와 일치하는 항목만 조회한다. 관리자는 전체 공지를 조회할 수 있다.
4. 조회 데이터와 사용자 질문을 분리하고, 조회 데이터 안의 지시를 실행하지 말라는 문장을 시스템 프롬프트에 포함했다.
5. JDK `HttpClient`로 Ollama 네이티브 API를 호출하며 별도 AI SDK는 추가하지 않았다.
6. Ollama JSON Lines를 읽는 즉시 SSE `token` 이벤트로 전달한다.
7. 완료 시 모델명, 첫 토큰 시간, 전체 응답 시간, 생성 토큰 수를 `done` 이벤트와 서버 로그에 남긴다. 질문 원문은 로그에 기록하지 않는다.
8. 연결 실패, 비정상 HTTP 응답, 시간 초과에는 내부 오류 대신 사용자용 안내를 보낸다.
9. 통합 테스트에서는 실제 모델을 호출하지 않고 `LocalLlmClient`를 가짜 응답으로 교체해 스트리밍과 권한 필터를 검증한다.

## 3. 설정과 실행

기본값은 Ollama의 `qwen3:4b` 모델이다. 환경 변수로 서버, 모델, 시간 제한을 바꿀 수 있다.

```properties
ERP_AI_BASE_URL=http://localhost:11434
ERP_AI_MODEL=qwen3:4b
ERP_AI_TIMEOUT_SECONDS=60
```

```bash
ollama pull qwen3:4b
ollama serve
./mvnw spring-boot:run
```

Ollama가 중지되어 있어도 ERP의 다른 기능은 실행되며, 챗봇만 모델 상태 확인 안내를 표시한다.

## 4. 트러블슈팅

### 스트리밍 API인데 답변이 한 번에 표시될 수 있음

- 원인: 응답 라인을 `toList()`로 먼저 모으면 Ollama 응답이 끝날 때까지 토큰 소비가 시작되지 않는다.
- 해결: 응답 스트림의 `Iterator`를 순차 소비해 각 JSON 라인을 읽는 즉시 SSE로 전달했다.
- 확인 지표: 실제 모델 검증에서 첫 토큰 시간과 전체 응답 시간이 분리되어 기록되어야 한다.

### 다른 사용자의 결재·부서 공지가 프롬프트에 포함될 위험

- 원인: 전체 수신함이나 전체 공지 조회 메서드를 그대로 재사용하면 화면 권한과 AI 문맥 권한이 달라질 수 있다.
- 해결: 현재 결재자의 미처리 결재와 전사·본인 부서 공지만 반환하는 전용 Mapper 쿼리를 추가했다.
- 재발 방지: 가짜 LLM이 받은 프롬프트에 허용 데이터는 포함되고 다른 사용자·부서 데이터는 없는지 통합 테스트에서 확인한다.

### 테스트가 로컬 모델 상태에 따라 실패할 수 있음

- 원인: 실제 모델의 설치 여부, 모델 다운로드 상태, 생성 결과는 CI에서 일정하지 않다.
- 해결: 통합 테스트에서는 네트워크 경계인 `LocalLlmClient`만 가짜 응답으로 교체했다. DB 조회, 권한 필터, Controller SSE는 실제 코드로 실행한다.

## 5. 성능 기록 기준

현재 실제 모델 성능 수치는 아직 측정하지 않았다. 다음 측정부터 아래 값을 같은 질문 세트와 같은 하드웨어 조건으로 저장한다.

1. 첫 토큰 시간(TTFT) p50·p95
2. 전체 응답 시간 p50·p95
3. 초당 생성 토큰 수
4. 시간 초과·실패율
5. 프롬프트 길이와 모델명

실제 수치가 확보되기 전에는 챗봇 성능이 개선됐다고 표현하지 않는다.
